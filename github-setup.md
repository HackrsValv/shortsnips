# GitHub Actions setup

Status: proposed files only. No repository created, workflow triggered or Worker deployed.

Create a public repository with the source at its root. Do not upload .dev.vars, node_modules, .wrangler, private sample/source data, secret files or internal conversation records. Configure the production environment and required reviewers where the account plan supports it. The workflow has only workflow_dispatch, no push/PR/schedule triggers. Default deploy=false only runs tests and a dry bundle. Explicit deploy=true requires owner go-ahead and reviewed config. GitHub Actions may use included minutes or incur costs; check plan and limits before running.

Secrets in repository Settings -> Secrets and variables -> Actions, or environment production:
- CLOUDFLARE_API_TOKEN: the stored Cloudflare deployment token.
- NOTION_TOKEN: stored Notion integration token.
- BUTTONDOWN_API_KEY: stored Buttondown key for the correct newsletter.
- SPIRAL_TOKEN: stored Spiral personal access token.
- ADMIN_TOKEN: a new high-entropy operator token generated and stored securely.
- NOTION_SETUP_TOKEN: a separate new high-entropy private bootstrap route identifier.
- NOTION_WEBHOOK_SECRET: generated by Notion during bootstrap; add later. Optional for first bootstrap.

Repository variable:
- CLOUDFLARE_ACCOUNT_ID: non-secret account ID, verified against Cloudflare.

Do not ask the user to paste any secret into chat. They enter the same vault-stored values themselves into GitHub's secret UI. This task cannot read/export the vault. The deployment token is available to Wrangler only; the runtime-secret stdin JSON excludes it. No runtime secrets are written to disk or echoed to workflow logs.

Before first deploy update wrangler.jsonc with actual NOTION_DATA_SOURCE_ID, NOTION_WORKSPACE_ID, tag/property names and types, English language and verified Spiral style/workspace/template if available. Subscription ID is filled after bootstrap. API sends must stay off. Current content template is still under owner review, so do not run generation.

The first deploy creates the code/bindings, then bulk-installs runtime secrets. Bootstrap accepts only the one-time verification receipt. Final signed-content ingress requires NOTION_WEBHOOK_SECRET plus the correct subscription ID. Do not use ordinary push as a deploy trigger or place secrets in workflow code. If secret installation fails, the first bootstrap cannot process unsigned notes; inspect and repair through the approved workflow.

The workflow includes third-party GitHub actions pinned to major tags; lock their full verified commit SHAs as a hardening step before production activation if required by the owner's repository standard. Dependencies are lockfile-pinned and tested. No auto-upgrade/dependabot workflow is configured.
